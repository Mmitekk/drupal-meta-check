HTML-инструмент одним файлом, без зависимостей: сверяет живые `<title>`, meta `description` и `H1` сайта на Drupal (и любом другом) с сохранённым снимком SEO-аудита. Сделан для рутинной проверки «поправил title — а он действительно выкатился?».

## Как это работает

Таблица аудита (URL, код ответа, язык, H1, Title, Description, число дубликатов Title/Description, длина текста) встроена прямо в `index.html`. Кнопка сверху загружает каждую страницу вживую и построчно сверяет её с отчётом.

## Возможности

- **Проверить актуальные данные** — загружает каждую страницу (через публичные CORS-прокси, по 4 параллельно) и показывает три метки на строку: H1 / Title / Description, каждая `=` (совпадает) или `≠` (отличается от отчёта).
- **Дубли** — раскройте строку и увидите всю группу дублей, как в попапе Топвизора: все страницы с тем же H1/Title/Description, текущая помечена «эта страница»; фильтр «С дублями» собирает их все разом.
- **Подозрение на 404** — Drupal на несуществующих адресах отдаёт главную страницу; инструмент помечает страницы, у которых каноническая ссылка указывает на главную или title говорит «Страница не найдена».
- **Черновики** — каждая строка разворачивается в редактор: впишите новый Title / Description, следите за числом символов (с меткой рекомендуемого диапазона 40–70 / 120–180), а после деплоя сверьте черновик с живой страницей. Черновики хранятся в `localStorage`.
- **Мягкое сравнение** — по умолчанию игнорирует регистр, пунктуацию и лишние пробелы; одной галочкой переключается на строгое посимвольное.
- **Фильтры и экспорт** — поиск по URL, фильтры по статусу (отличается / совпадает / ошибки / не проверено / черновик ≠ сайт), экспорт всего в CSV.
- **Замена данных** — вставьте другой аудит массивом JSON (блок «Данные отчёта»), чтобы использовать инструмент для другого сайта.

## Начало работы

1. Откройте `index.html` в браузере — работает прямо с диска или через GitHub Pages.
2. Нажмите **Проверить актуальные данные** и подождите (около минуты на 100 страниц через прокси).
3. Кликните по любой строке — раскроется сравнение «в отчёте ↔ на сайте» и редакторы черновиков.

Ни сборки, ни зависимостей, ни бэкенда. Наружу уходят только загрузки самих страниц; результаты и черновики остаются в вашем браузере.

## Универсальный режим — проверка любого сайта

Встроенный отчёт — просто пример. Чтобы проверить свой сайт: откройте «Своя проверка» под панелью, вставьте адрес `sitemap.xml` (или просто список ссылок) и нажмите «Создать проверку». Дальше:

1. Дождитесь живой проверки — страницы появятся с меткой `○ нет базы`.
2. Нажмите «◉ Зафиксировать базу» — полученные значения станут базой сравнения.
3. После правок на сайте снова нажмите «Проверить актуальные данные» — в строках будет видно, что именно изменилось с момента снимка (`=` / `≠`).

Текущая сессия (список адресов, база, черновики, живые результаты) хранится в браузере и переживает перезагрузку страницы; «Вернуть встроенные данные» возвращает исходный отчёт.

## Обновление данных аудита

Откройте **Данные отчёта** под панелью и вставьте JSON-массив:

```json
[
  {
    "url": "https://example.com/",
    "code": "200",
    "lang": "ru",
    "h1": "…",
    "title": "…",
    "description": "…",
    "dupTitle": "0",
    "dupDescription": "0",
    "textLength": "6930"
  }
]
```

Обязательное поле только `url`. Импортированные данные хранятся в браузере; кнопка **Вернуть встроенные данные** возвращает исходный снимок. `urls.txt` в корне репозитория — простой список проверенных URL.

## GitHub Pages

Каждый пуш в `main` автоматически выкладывает сайт через GitHub Actions workflow (`.github/workflows/pages.yml`) — ничего настраивать вручную не нужно.

Живая версия: **https://mmitekk.github.io/drupal-meta-check/**

Если Pages для репозитория ещё ни разу не включался и workflow не сможет включить его сам, сделайте это один раз вручную: **Settings → Pages → Source: «GitHub Actions»**, затем перезапустите workflow (Actions → Deploy to GitHub Pages → Run workflow).

## Приватность

Встроенный снимок содержит только публичные мета-данные публичного сайта — без токенов, ключей, паролей и ссылок на закрытые отчёты.
